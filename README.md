## SharePoint Online 原生保护到底给了你什么

微软给的是一套容灾设计，备份的成分很有限。具体拆开看：

- **回收站**：删除的文件先进第一阶段回收站，两阶段合计保留约 93 天，期间可手动恢复。
- **版本历史**：默认每个文件最多保留 500 个版本，可以往上调。
- **文档库回滚**：能把整个文档库撤销回过去 30 天内的任意时间点，对付批量误删和早期勒索加密有用。
- **平台层备份**：微软默认每 12 小时对 SharePoint 数据做一次平台备份，保留 14 天；元数据以 5–10 分钟的节奏推送到冗余 Azure 存储。
- **底层架构**：文件内容同时写入主、次两个数据中心区域；元数据存在 Azure SQL 里，提供最长 14 天的时间点恢复。

这些机制能处理“上午误删、下午找回”的场景。它们处理不了的是：93 天后才发现文件没了、勒索软件潜伏超过回滚窗口、合规要求保留一年以上的历史版本、以及“我要的不是整个站点回滚，而是从三个月前的备份里抽出一份合同”。

Resilio 的一篇备份综述里引述过一句关键的话："Even Microsoft recommends regular third-party backups as part of their best practices for SharePoint, as these native capabilities don't protect against data loss in many scenarios." 微软自己都建议做第三方备份，因为共享责任模型下，服务可用性归微软，你的数据归你。

## Microsoft 365 Backup：官方付费备份，以及它的小字条款

微软现在有正式的备份产品 Microsoft 365 Backup，计费方式是**受保护数据每 GB 每月 $0.15，还原免费**。恢复点密度很高：过去两周内每 10 分钟一个，2–52 周前每周一个快照；恢复窗口可在 3 个月、6 个月、1 年、2 年之间配置，默认 1 年。还原速度也不错，官方标称最多 1,000 个站点时中位速率可达 1–3 TB/小时。备份存在微软自己的信任边界内，采用 append-only 存储防止恶意覆盖。

多数介绍文章到这就结束了，但三个限制直接影响采购决策：

1. **SharePoint 站点级还原会覆盖一切**。整站还原是把站点回滚到那个时间点，该时点之后的所有内容和元数据都会被覆盖。只想找回一个文件？官方文档里 SharePoint 的“通过文件版本恢复”还标注着 coming soon。
2. **默认保留期固定为 1 年**，恢复点频率随工作负载和备份年龄变化。
3. **不支持跨用户、跨组织还原**，恢复目标只能是原工作负载。

算一下钱：200GB 的站点数据走 Microsoft 365 Backup，每月 $30，一年 $360。这个价格换来的是极简管理和数据不出微软边界，对很多团队合理。但如果你需要细粒度恢复、独立于微软的副本、或者更长的保留期，就该看第三方了。

## 常见问题

**SharePoint Online 数据存在微软那里，还需要额外备份吗？**
需要，如果你的风险窗口超过原生保护。微软的双区域写入防的是数据中心故障，防不了超过 93 天才发现的误删、潜伏期长的勒索软件、以及合规要求的长期保留。微软自己的最佳实践也建议做第三方备份。

**删除的 SharePoint 文件到底能保留多久？**
两阶段回收站合计约 93 天，从删除那一刻算起，不是从进入第二阶段算起。93 天之后，回收站救不了你，只能靠独立备份。

**能从 Microsoft 365 Backup 里只恢复一个文件吗？**
目前不能。SharePoint 的还原粒度是站点级，整站还原会覆盖该时间点之后的全部内容；文件版本还原在官方文档里还是 coming soon 状态。这正是 Acronis 这类第三方方案的主要卖点——单文件、单文件夹级恢复。

**200GB 的 SharePoint 数据做备份一年要花多少钱？**
走 Microsoft 365 Backup 是 $360/年；走 Sharktech 年付方案是 $24/年 含 200GB，超额每 GB 再加 $0.12。价格差距很大，但两者计费对象和恢复能力不同，前者按受保护数据量计费且是站点级还原，后者按存储容量计费并支持细粒度恢复——按你实际需要的恢复粒度选。
